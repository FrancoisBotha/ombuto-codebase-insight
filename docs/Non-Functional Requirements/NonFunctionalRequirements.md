# Non-Functional Requirements

| ID | Sub-System | Description | Status | Epic |
|----|-----------|-------------|--------|------|
| NFR-001 | Repo & Pipeline | The analysed repo is read-only and untrusted. git always runs with an argument array (no shell), `--no-textconv`, no external diff and `core.fsmonitor` disabled. Nothing from the repo is executed. | NEW | epic_01_OPEN_AND_INVENTORY |
| NFR-002 | Repo & Pipeline | The renderer has no filesystem, git or SQLite access. Data reaches it only through typed, read-only IPC queries. `contextIsolation` and `sandbox` stay on and `nodeIntegration` stays off. | NEW | epic_01_OPEN_AND_INVENTORY |
| NFR-003 | Repo & Pipeline | The worker is the only writer to `insight.db`. Each stage commits in its own transaction and is idempotent: re-running it for the same commit gives the same rows. | NEW | epic_01_OPEN_AND_INVENTORY |
| NFR-004 | Repo & Pipeline | A worker crash or a stage error marks the run `failed` with the error recorded and shown. The app stays up, and the UI stays responsive while indexing. | NEW | epic_01_OPEN_AND_INVENTORY |
| NFR-005 | Repo & Pipeline | Reopening an already analysed, unchanged repo of about 100k lines shows Size & Inventory within 1 second. | NEW | epic_01_OPEN_AND_INVENTORY |
| NFR-006 | Complexity | Extract files plus Transform for a repo of about 100k lines finishes within 2 minutes on a typical laptop. Indexing shows per-file progress. | NEW | epic_02_FUNCTION_COMPLEXITY |
| NFR-007 | Complexity | Grammars load only from `resources/grammars/` and are checked against the sha256 in `grammars.json`. A grammar that fails to load, or a parse that throws, affects only that language's or blob's rows, never the run. | NEW | epic_02_FUNCTION_COMPLEXITY |
| NFR-008 | Hotspots | History extraction streams git output rather than buffering it, and handles 10k commits within 60 seconds on a typical laptop, with progress shown on Indexing. | NEW | epic_03_HOTSPOTS |
| NFR-009 | Ownership & History | Blame runs with a bounded number of concurrent git processes, skips binary and generated files, and reports progress. A blame failure on one file is recorded and doesn't fail the stage. | NEW | epic_04_OWNERSHIP_AND_HISTORY |
| NFR-010 | Overview & Reporting | The Load reporting stage can be re-run on its own from existing `metric_*` rows without re-parsing or re-reading history, and gives identical rows for the same inputs. | NEW | epic_05_OVERVIEW_AND_HEALTH_SCORE |
| NFR-011 | Structure | Graph layout runs off the UI thread (a web worker in the renderer). A graph of 300 modules lays out and renders within 2 seconds. Co-change pair generation is bounded: very large commits above a documented file count are skipped. | NEW | epic_06_MODULE_STRUCTURE |
| NFR-012 | Code Quality | Duplication detection uses windowed fingerprints indexed by hash and stays within the NFR-006 time budget on a 100k-line repo. Generated and vendored files are excluded from all quality findings. | NEW | epic_07_CODE_QUALITY |
| NFR-013 | Dependencies | Outbound lookups send only ecosystem, package name and version. No paths, file contents or repo identifiers. A unit test checks the request payloads. | NEW | epic_08_DEPENDENCY_HEALTH |
| NFR-014 | Dependencies | Network failures and timeouts never fail the run. Affected packages become `not_checked` and Indexing logs why. Requests are rate limited and use a generic client User-Agent. | NEW | epic_08_DEPENDENCY_HEALTH |
| NFR-015 | Secrets | The full secret value is never written to the database, logs, IPC payloads or the Indexing log. Only masked previews leave the scanner. A unit test asserts this on a fixture containing known fake keys. | NEW | epic_09_SECRETS_SCAN |
| NFR-016 | AI · Ask | AI output is rendered as sanitised Markdown with no raw HTML, is display-only and is never executed. Repo content can contain prompt injection, so links and code in answers are inert text. | NEW | epic_10_ASK_LOCAL_AI |
| NFR-017 | AI · Ask | In this epic only a loopback Ollama endpoint (`localhost`, `127.0.0.1`, `::1`) is accepted. A non-loopback endpoint would send code off the machine without the guard. It is rejected with an explanation until Epic 11 routes it through the guard. | NEW | epic_10_ASK_LOCAL_AI |
| NFR-018 | AI · Ask | No code in `raw_*`, `metric_*` or `report_*` paths reads `ai_*`. The schema test and a module-boundary test enforce it. | NEW | epic_10_ASK_LOCAL_AI |
| NFR-019 | AI · Guard | There is exactly one code path to any remote provider, and it always runs the guard. A test asserts that no provider client can be called except through the guarded send. | NEW | epic_11_REMOTE_AI_WITH_GUARD |
| NFR-020 | AI · Guard | API keys never appear in `electron-store`, the database, logs, IPC responses or the renderer. The renderer only learns "key set / not set". | NEW | epic_11_REMOTE_AI_WITH_GUARD |
| NFR-021 | AI · Explanations | Every AI output uses the AI block pattern and shows provider, model and commit. Computed values such as `report_hotspot.reason` are never replaced or edited by AI text. A test asserts that the load stage reads no `ai_*` table. | NEW | epic_12_AI_EXPLANATIONS |
| NFR-022 | AI · Local CLI | CLI runs have a timeout, are killed on cancel, run with a working directory outside the repo when tools are off, and never inherit API keys from Codebase Insight's own key store. | NEW | epic_13_LOCAL_CLI_AND_LLM_GUARD |
| NFR-023 | Re-analysis & Trends | Re-analysis after a pull that changes 50 files on a repo of about 100k lines completes within 10 seconds on a typical laptop. | NEW | epic_14_FAST_REANALYSIS_AND_TRENDS |
| NFR-024 | Re-analysis & Trends | An incremental run produces the same `metric_*` and `report_*` rows as a full run from an empty database for the same commit (an equivalence test on a fixture repo). | NEW | epic_14_FAST_REANALYSIS_AND_TRENDS |
